# IntelliJ plugin (experimental)

The SpringGraph plugin shows the processor's results in IntelliJ IDEA. It does not analyse code itself: it reads the
[JSON report](reference/report-json.md) that the processor writes on every compile. What you see is exactly what the last
build reported, including a failed strict build.

Without the plugin, findings already show up in the Build tool window as clickable warnings or errors, because IntelliJ
runs the processor as part of the Gradle or Maven build.

## What it adds

- **Gutter icons** on every constructor parameter of an analysed component:

    | Icon | Meaning | Click |
    |---|---|---|
    | Check | Validated | Goes to the chosen bean |
    | Information | Runtime boundary, Spring Data repository or `@Value`: not validated by design | |
    | Warning | Unsupported (SG006, SG008) | |
    | Error | Missing (SG001) or ambiguous (SG007) | Ambiguous: choose among the candidates |

    The tooltip shows the classification, the rule that chose the bean (`via @Primary`), and the findings for that
    parameter. Turn the icons off under **Settings | Editor | General | Gutter Icons | SpringGraph dependency**.
- **SpringGraph tool window** (right side): one entry per module, with its mode and coverage, every finding, the analysed
  components and their dependencies, and the excluded classes. Double-click or press Enter to go to the source. Type to
  search.

## Requirements

- IntelliJ IDEA 2025.3 or newer.
- The processor `io.github.mrsluffy:springgraph-processor` with `-Aspringgraph.mode=advisory` or `strict`. Versions up
  to `0.1.0-rc.3` do not write `graph.json`: use the next release, or build the processor from source. See
  [Getting started](getting-started.md).

## Install

The plugin is not on JetBrains Marketplace yet. Install it from disk:

1. Get the zip: download the `springgraph-intellij` artifact of the latest
   [IntelliJ plugin workflow run](https://github.com/MrSluffy/spring-graph/actions/workflows/intellij.yml), or build it
   (below).
2. In IntelliJ: **Settings | Plugins | gear icon | Install Plugin from Disk**, choose the zip, and restart.

## Use

1. Build the project (**Build | Build Project**). The reports are reloaded after every build started from the IDE.
2. Open the **SpringGraph** tool window.
3. After a build from the terminal, click **Refresh** in the tool window. The IDE does not notice terminal builds.

The plugin looks for `graph.json` in each module's IntelliJ output directory and in the standard Gradle
(`build/classes/java/main`) and Maven (`target/classes`) output directories.

## Limitations

- Markers are matched to constructors using parameter count and erased types. Icons are hidden when those no longer
  match the last build. Qualifier-only changes with unchanged types may leave the old marker and navigation target
  visible until the next build.
- Constructors generated by Lombok have no source to attach icons to. Their dependencies are listed in the tool window.
- Only main sources (`compileJava`), like the processor setup in Getting started.

## Build from source

The plugin is a separate Gradle build in `springgraph-intellij/`. By default it downloads IntelliJ IDEA 2025.3
(about 1.5 GB). To use an installed IDE of the same version line instead, set its install directory in
`~/.gradle/gradle.properties`:

```properties
springgraph.intellijLocalPath=C:\\Program Files\\JetBrains\\IntelliJ IDEA 2025.3
```

Then:

```
./gradlew -p springgraph-intellij build buildPlugin # tests and build/distributions/springgraph-intellij-<version>.zip
./gradlew -p springgraph-intellij verifyPlugin    # JetBrains Plugin Verifier
./gradlew -p springgraph-intellij runIde          # a sandbox IDE with the plugin installed
```
