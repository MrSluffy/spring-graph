## Phase 1: Early feasibility experiments ✅

**Deliverable:** separate go/no-go decisions for validation and construction.

- **Validation spike:** the processor reported a missing binding and a constructor cycle, and showed runtime boundaries.
  Led to [Gate A](gates.md) passing.
- **Integration spike** (`springgraph-spring`, `ConstructionRegistrar`): a handwritten generated-style construction
  callback, registered by attaching an instance supplier to the scanned bean definition.
  Verified in a plain Spring context: availability, singleton identity, container-provided dependencies,
  `@PostConstruct` and `@PreDestroy`, `BeanPostProcessor` behavior, no duplicate beans, and a proxy (from a hand-rolled
  JDK-proxy post-processor) injected instead of the raw target. Not verified: real `@Transactional`/AOP auto-proxying and
  Spring Boot. See [Spring integration](../architecture/spring-integration.md).
  Gate B stays open because no benefit was measured.

## Phase 2: Minimal repository and processor ✅

**Deliverable:** reliable source discovery.

- `springgraph-processor` module with compiler tests (compile-testing).
- Opt-in through `-Aspringgraph.mode=advisory|strict`; does nothing without it.
- Direct stereotypes: `@Component`, `@Service`, `@Repository`, `@Controller`, `@RestController`.
- Constructor rule: exactly one non-private constructor (Lombok-generated constructors count).
- Processing rounds: candidates collected by name every round, analysis once in the final round, so types generated by
  other processors (Lombok, MapStruct) are visible.

---

## Phase 3: Useful validation MVP ✅

**Deliverable:** validation that adds value without runtime changes.

- Concrete and non-generic interface resolution.
- Diagnostics: SG001 missing, SG003 eager constructor cycle, SG004 scope, SG005 constructor, SG006 unsupported feature,
  SG007 ambiguous, SG008 qualifier, SG009 configuration. SG002 is reserved. See the
  [diagnostics reference](../reference/diagnostics.md).
- Runtime boundaries declared with `-Aspringgraph.runtimeBoundaries`, with SG009 checks for typos (with "Did you
  mean"), stale and ineffective declarations.
- Spring Data repositories and `@Value` parameters recognized and never counted as validated.
- Deterministic report at `META-INF/springgraph/graph.txt`, and a note when less than half is validated.

---

## Phase 4: Real application pilot ✅

**Deliverable:** evidence that adoption helps developers.

- Four applications: an in-repo Boot + JPA pilot, spring-petclinic, spring-petclinic-rest, and a Maven + Lombok project.
- Three classes of false positives found and fixed, each with a regression test.
- Seeded mistakes caught at compile time in about 3 s, against about 11 s for a Boot context test.
- Clean-compile overhead within run-to-run noise on the two small Gradle projects. On spring-petclinic-rest only
  annotation processing was measured (`javac -proc:only`, about 400 ms median difference), not the full build.

Details: [pilot results](pilot-results.md).

## Phase 6: Optional construction extension ⏸️

**Deliverable:** an optional, evidence-backed extension.

Not started, by design: it only proceeds if [Gate B](gates.md) passes. Open questions: does an AOT-compatible variant
need a `BeanRegistrationAotProcessor`, and does generated construction measurably beat Spring and Spring AOT on a
realistic application.

| Item | Status |

| Generic bindings | ❌ Not started |
| Limited `@Bean` analysis | ❌ Not started. Next candidate: removes most manual boundary declarations |
| Multi-module metadata | ❌ Not started; needs a design first |
| Incremental-processing support | ❌ Not started, never tested |
| Dependency explanation tools | 🟡 The report shows why a candidate was chosen (`via @Primary`); no dedicated explain feature |
| Wider version compatibility | ❌ Two Spring lines tried; no compatibility matrix in CI |

Still not validated after the qualifier work: several candidates matching one qualifier, `@Priority`, and candidates
named by `@Named` or `@ManagedBean`.

## Suggested order from here

1. Finish Phase 5: fix the Central validation, a full release run, `0.1.0`.
2. Get one or two outside users. The plan's success criteria need evidence from people other than the maintainers.
3. Phase 7: limited `@Bean` analysis, then incremental-build behavior, then a version matrix in CI.
4. Revisit Gate B only with measurements on a realistic application.
